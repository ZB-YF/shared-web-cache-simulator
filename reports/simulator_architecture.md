# Simulator Architecture and Implementation

The simulator replays local HTTP request traces without making network connections. Resource metadata is indexed by the full URL constructed from scheme, host, and path. The loader validates numeric fields and resource references, converts timestamps to timezone-aware values, and stably sorts requests so equal timestamps retain their source order. All clients share one initially empty, byte-limited cache.

Cache storage and replacement decisions are separated. The cache owns capacity accounting and insertion-order snapshots, while each policy maintains its own ranking metadata. On a hit, the simulator applies the configured hit latency and records zero origin traffic. On a miss, it uses the resource's origin latency and counts its full size as origin traffic. An oversized resource is served without insertion or eviction. For fitting resources, the cache previews the required victim set before committing removals; this supports the Custom policy's admission filter while keeping FIFO, LRU, and LFU on the same processing path.

Each request produces an immutable result containing hit status, response time, traffic, ordered evictions, and a cache snapshot. A separate statistics module aggregates global and per-client metrics. Fresh cache, policy, and statistics objects isolate experiment runs. CSV/JSON exports retain request logs, counts, configuration, and input/source hashes, while seeded synthetic batches preserve exact input traces. This separation supports reference validation, reproducible comparisons, and independent review of metric calculations.
